### Execution, PTY, and assurance flow

- Headless execution validates argv, creates a private output directory, captures at most 1 MiB per stream while recording total bytes/truncation, scrubs the default environment, and hashes the resolved executable when readable. [process.go:25-122](../../internal/execution/process.go#L25-L122) [process.go:158-270](../../internal/execution/process.go#L158-L270)
- Local mode is explicitly not a sandbox. Restricted Docker requires a pinned `@sha256:` image, no pass-env, no network, read-only root, dropped capabilities, resource limits, and a non-fallback error when Docker is unavailable. [process.go:101-156](../../internal/execution/process.go#L101-L156) [process.go:191-204](../../internal/execution/process.go#L191-L204)
- PTY mode is Linux/darwin-only. The broker permits one attached writer, retains a bounded 32 KiB ring, handles input/resize/detach, and captures the slave output. [pty_linux.go:74-228](../../internal/execution/pty_linux.go#L74-L228) [pty_darwin.go:103-261](../../internal/execution/pty_darwin.go#L103-L261) [attach.go:17-116](../../internal/execution/attach.go#L17-L116)
- Verification materializes a fresh candidate copy per check, refuses preexisting report files, runs the check, stores output/report blobs, interprets the result, and rejects the result if source inputs changed during the check. [verify.go:167-246](../../internal/assurance/verify.go#L167-L246)
- Parsers intentionally distinguish process completion from test outcome. Missing/malformed/truncated/timed-out results are `ERROR` or `INCONCLUSIVE`; exit-zero means only configured process success, not coverage or correctness. [parse.go:22-53](../../internal/assurance/parse.go#L22-L53) [parse.go:69-160](../../internal/assurance/parse.go#L69-L160)
