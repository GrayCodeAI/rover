# Rover security and verification audit

Audit scope: read-only review of the current tree at the time of inspection, including all Go packages and tests, the Python/TypeScript/Go SDKs and tests, JSON schemas, CI/release workflows, scripts, security/architecture/status/validation documents, and the retained validation artifacts. Local citations use repository-relative links and literal `file:line` references. The findings distinguish observed behavior from code-review hypotheses; no exploit, certification, live-provider, hosted-CI, or independent-host claim is made.

## Security boundaries and concrete findings

### Takeaway

Rover has a coherent and unusually candid local-advisory boundary: explicit argv, strict JSON, frozen snapshot bytes, bounded output, transactional SQLite records, scoped bearer grants, and separate execution/evidence/review concepts are real strengths. The dominant risks are integrity and lifecycle gaps rather than an advertised sandbox: the current tree is not bound by the retained validation manifests, cgo-free release artifacts cannot open a store, the task budget ledger has no production caller, same-user workers can race filesystem/state checks, and a detached task trusts a mutable frozen-config record. These are serious for an alpha that presents itself as verification/evidence infrastructure, but they do not contradict the repository's explicit statement that local execution is not a sandbox ([docs/SECURITY_MODEL.md:3-13](../../docs/SECURITY_MODEL.md#L3-L13)).

### Cited Findings

#### Concrete strengths

- **Explicit command boundary and bounded process handling.** `execution.Run` accepts argv rather than inserting a shell, rejects NUL/oversized arguments, applies timeouts, captures at most 1 MiB per stream, uses isolated child HOME/TMP/cache paths, and does not silently promote incomplete output to a passing check. ([internal/execution/process.go:1-3](../../internal/execution/process.go#L1-L3), [internal/execution/process.go:25-82](../../internal/execution/process.go#L25-L82), [internal/execution/process.go:158-217](../../internal/execution/process.go#L158-L217), [internal/execution/process.go:237-285](../../internal/execution/process.go#L237-L285)) Unix workers use a separate process group and cancellation attempts group cleanup. ([internal/execution/process_unix.go:11-28](../../internal/execution/process_unix.go#L11-L28))
- **Conservative source admission.** Commits are read with fixed Git arguments and scrubbed Git configuration; worktree capture rejects symlinks, submodules, unresolved LFS pointers, unsafe paths, case collisions, special files, and size limits, then freezes bytes in content-addressed objects. ([internal/source/source.go:44-78](../../internal/source/source.go#L44-L78), [internal/source/source.go:114-170](../../internal/source/source.go#L114-L170), [internal/source/source.go:178-345](../../internal/source/source.go#L178-L345)) The code and documentation correctly state that two identical worktree reads are not a filesystem-atomic transaction. ([internal/source/source.go:324-334](../../internal/source/source.go#L324-L334), [README.md:174-176](../../README.md#L174-L176))
- **Strict public decoding and candidate binding.** Duplicate keys, case-aliased fields, null required safety fields, unknown nested fields, NULs, unsafe relative paths, and invalid parser contracts are rejected or semantically validated. ([internal/config/config.go:27-68](../../internal/config/config.go#L27-L68), [internal/config/config.go:93-137](../../internal/config/config.go#L93-L137), [internal/config/config.go:186-239](../../internal/config/config.go#L186-L239), [internal/wire/json.go:13-94](../../internal/wire/json.go#L13-L94)) Required decisions bind the check spec digest and candidate ID, and incomplete/error/truncated results do not pass. ([internal/assurance/parse.go:22-52](../../internal/assurance/parse.go#L22-L52), [internal/assurance/verify.go:51-107](../../internal/assurance/verify.go#L51-L107))
- **SQLite and blob hygiene.** SQL is fixed and values are bound; records/events/idempotency operations are transactional; WAL, FULL synchronous mode, foreign keys, busy timeout, content-addressed blobs, digest checks, and the online backup API are used. ([internal/store/sqlite.go:219-258](../../internal/store/sqlite.go#L219-L258), [internal/store/sqlite.go:327-451](../../internal/store/sqlite.go#L327-L451), [internal/store/sqlite.go:467-535](../../internal/store/sqlite.go#L467-L535), [internal/store/sqlite.go:610-713](../../internal/store/sqlite.go#L610-L713))
- **Scoped API authority and transport refusal.** Grant tokens are random and stored by digest, with project/audience/tool scope, expiry, and revocation. HTTP requires bearer auth, rejects browser Origins, bounds headers/messages/concurrency, refuses redirects on the client, and requires TLS for non-loopback listeners. ([internal/access/grants.go:46-119](../../internal/access/grants.go#L46-L119), [internal/mcp/http.go:19-140](../../internal/mcp/http.go#L19-L140), [internal/mcp/client.go:34-126](../../internal/mcp/client.go#L34-L126)) The service excludes grant/review/signing/publish/merge tools and rechecks grant state at call time. ([internal/service/service.go:64-119](../../internal/service/service.go#L64-L119), [internal/service/service.go:120-153](../../internal/service/service.go#L120-L153))
- **Evidence honesty and reversibility.** Attempts remain separate, replay creates a new investigation, formal-scope PASS is capped, signatures use domain separation, backups verify hashes and revoke grants, and instruction undo refuses a changed file. ([internal/tasks/tasks.go:329-455](../../internal/tasks/tasks.go#L329-L455), [internal/assurance/counterfactual.go:196-224](../../internal/assurance/counterfactual.go#L196-L224), [internal/assurance/parse.go:55-68](../../internal/assurance/parse.go#L55-L68), [internal/attestation/sign.go:109-164](../../internal/attestation/sign.go#L109-L164), [internal/archive/archive.go:215-256](../../internal/archive/archive.go#L215-L256), [internal/integration/instructions.go:184-220](../../internal/integration/instructions.go#L184-L220))
- **Tests cover useful negative paths.** Current tests cover malformed JSON/transcripts, static symlink/path rejection, parser incompleteness, grant scope/revocation, duplicate in-flight IDs, cancellation, backup tamper detection, signature key mismatch, learning overlap, and no-fallback admission. ([internal/config/config_test.go:15-133](../../internal/config/config_test.go#L15-L133), [internal/agents/agents_test.go:55-118](../../internal/agents/agents_test.go#L55-L118), [internal/source/source_test.go:50-76](../../internal/source/source_test.go#L50-L76), [internal/mcp/protocol_test.go:75-160](../../internal/mcp/protocol_test.go#L75-L160), [internal/archive/archive_test.go:18-152](../../internal/archive/archive_test.go#L18-L152))

#### F-01 — High: current source/evidence manifests are stale and the local installer check is not a trust anchor

`SOURCE_MANIFEST.json` identifies itself as a source-package inventory, while `doctor --verify` checks only the files listed in that same co-located manifest. ([SOURCE_MANIFEST.json:2-4](../../SOURCE_MANIFEST.json#L2-L4), [internal/install/verify.go:25-80](../../internal/install/verify.go#L25-L80)) The verifier has no completeness check, no external signature, and explicitly skips the manifest itself. ([internal/install/verify.go:51-53](../../internal/install/verify.go#L51-L53)) A modified file plus a modified local manifest can therefore pass a local hash check; this is not signed installer trust.

A read-only hash comparison against the current tree found 57 mismatches among 197 `SOURCE_MANIFEST.json` entries and 49 mismatches among 76 entries in `docs/validation/v0.2.0/tested-code-manifest.json`; 11 current Go files are absent from the historical tested-code manifest. The current binary's `doctor --verify --json` fails immediately with `size mismatch .github/workflows/ci.yml: got 1545 want 1233`. The retained report nevertheless says the doctor check was verified and that a fresh package matched the tested manifest. ([STATUS.md:151-163](../../STATUS.md#L151-L163), [docs/validation/v0.2.0/REPORT.md:95-111](../../docs/validation/v0.2.0/REPORT.md#L95-L111), [docs/validation/v0.2.0/summary.json:47-54](../../docs/validation/v0.2.0/summary.json#L47-L54)) Treat those artifacts as historical observations, not evidence for the current HEAD.

#### F-02 — High: release-attached Darwin artifacts are compile-only, not functional Rover stores

The `!cgo` store returns `errNoCGO` for every database operation, and `Open` creates state directories before returning that error. ([internal/store/sqlite_stub.go:31-45](../../internal/store/sqlite_stub.go#L31-L45), [internal/store/sqlite_stub.go:144-176](../../internal/store/sqlite_stub.go#L144-L176)) The cross-build target and release workflow nevertheless attach `rover-darwin-amd64` and `rover-darwin-arm64`. ([Makefile:36-43](../../Makefile#L36-L43), [.github/workflows/release.yml:35-40](../../.github/workflows/release.yml#L35-L40), [.github/workflows/release.yml:60-66](../../.github/workflows/release.yml#L60-L66)) The current cross-built arm64 binary returned `store requires CGO and system SQLite` for `status` while `version` succeeded. The CI document calls the targets non-functional stubs, but the release artifact list does not exclude them. ([docs/CI.md:21-28](../../docs/CI.md#L21-L28))

#### F-03 — High for the release gate: the current vulnerability target fails

`make vulncheck` invokes `golang.org/x/vuln/cmd/govulncheck@latest` rather than a repository-pinned scanner/tool version. ([Makefile:53-55](../../Makefile#L53-L55)) On the observed Go 1.26.5 environment, the command failed with six reachable standard-library advisories: GO-2026-6218 (`net/url`), GO-2026-6090 (`crypto/tls`), GO-2026-6089 (`net/http`), GO-2026-6088 (`encoding/xml`), GO-2026-5972 (`encoding/asn1`), and GO-2026-5026 (`net/http`/IDNA). The reported XML path reaches the candidate-controlled JUnit parser. ([internal/assurance/parse.go:176-207](../../internal/assurance/parse.go#L176-L207), [internal/mcp/http.go:169-176](../../internal/mcp/http.go#L169-L176), [internal/mcp/client.go:70-71](../../internal/mcp/client.go#L70-L71)) No exploit was attempted. The status document nevertheless describes `make vulncheck` as complete while recording advisories on a different toolchain state. ([STATUS.md:224-228](../../STATUS.md#L224-L228))

#### F-04 — High/Medium: JUnit and regression XML parsing have no explicit nesting bound

The JUnit parser limits bytes to 8 MiB and rejects DTD/entity markers, but then calls `encoding/xml.Decoder.Decode` and `Token` without a project-level depth limit. ([internal/assurance/parse.go:176-207](../../internal/assurance/parse.go#L176-L207)) The regression identity path also calls `xml.Unmarshal` on candidate-produced report bytes. ([internal/assurance/counterfactual.go:154-185](../../internal/assurance/counterfactual.go#L154-L185)) The current `govulncheck` result specifically identified the XML recursion advisory on the first path. This is a reachable untrusted-input hardening concern, not a demonstrated exploit. Add a deeply nested, bounded-but-large XML regression and enforce a depth/size policy before decoding.

#### F-05 — High integrity gap: a task's frozen verification config is not independently digest-bound at execution

`TaskRun` stores `ContractDigest` for the task spec and a mutable `FrozenConfig`, but has no frozen-config digest field. ([internal/model/model.go:201-223](../../internal/model/model.go#L201-L223)) Submission computes a request hash including the frozen config for `CreateOnce`, but does not persist that hash as an execution invariant. ([internal/tasks/tasks.go:108-118](../../internal/tasks/tasks.go#L108-L118)) `Execute` later trusts `r.FrozenConfig` directly. ([internal/tasks/tasks.go:415-421](../../internal/tasks/tasks.go#L415-L421)) A same-user process able to alter the controller SQLite record can therefore change required checks after dispatch without causing the task contract check to fail. This is within the documented same-user authority boundary, but it weakens the “frozen config” claim for hostile local workers; the candidate should not be assumed unable to edit controller state merely because its own workspace is isolated. There is no regression test that mutates `FrozenConfig` and requires refusal.

#### F-06 — Medium: detached supervisors aggregate pass-through secrets across task/check phases

The child process environment is scrubbed and only receives its own declared `pass_env`, which is a real strength. ([internal/execution/process.go:101-122](../../internal/execution/process.go#L101-L122)) However, the detached task supervisor receives the union of task pass-through variables and every frozen check's pass-through variables. ([internal/tasks/tasks.go:134-153](../../internal/tasks/tasks.go#L134-L153)) Workflow supervisors do the same across all nodes and checks. ([internal/workflow/workflow.go:228-252](../../internal/workflow/workflow.go#L228-L252)) A same-user child can inspect parent process metadata such as `/proc/<ppid>/environ` on Linux, so the union is observable even when the direct child environment is clean. This is not an OS isolation claim; it is a missing secret-minimization boundary and should be tested with two phases carrying different credentials.

#### F-07 — Medium: source and workspace checks have acknowledged TOCTOU windows

`ReadRegular` checks every component with `Lstat`, then opens the pathname without `O_NOFOLLOW`; the comment explicitly says same-user TOCTOU is not prevented. ([internal/source/source.go:126-170](../../internal/source/source.go#L126-L170)) `InputsUnchanged` repeats the same check/read pattern after a check runs. ([internal/source/source.go:400-410](../../internal/source/source.go#L400-L410)) `Materialize` creates/check directories and then opens files by pathname, while `ReplaceWorkspace` removes files after a non-atomic comparison. ([internal/source/source.go:356-397](../../internal/source/source.go#L356-L397), [internal/source/compose.go:156-169](../../internal/source/compose.go#L156-L169)) A concurrent workspace writer can swap a component or file between inspection and use. Existing tests cover static nested symlinks but not a race. ([internal/source/source_test.go:217-224](../../internal/source/source_test.go#L217-L224))

The state-root guard has the same shape: it checks ancestors, calls `MkdirAll`, checks again, and chmods a pathname. ([internal/store/sqlite.go:120-154](../../internal/store/sqlite.go#L120-L154)) `Open` validates `rover.db` with `Lstat` and then passes the pathname to SQLite and chmods it by path. ([internal/store/sqlite.go:190-215](../../internal/store/sqlite.go#L190-L215)) These are meaningful for a hostile same-user worker, although the repository explicitly declines to treat that worker as an OS-isol adversary. Prefer descriptor-relative `openat`-style operations, `fstat`, and `unlinkat`-style operations where the platform supports them.

#### F-08 — Medium: reversible instruction apply/undo can overwrite a concurrent edit

`Apply` first recomputes a preview and compares its hash, but then rereads the file and writes the planned content without comparing that reread to `p.Before` immediately before replacement. ([internal/integration/instructions.go:151-182](../../internal/integration/instructions.go#L151-L182)) `Undo` similarly checks the current digest and later replaces/removes the path, leaving a race window. ([internal/integration/instructions.go:184-220](../../internal/integration/instructions.go#L184-L220)) `read` itself uses `Lstat` followed by `ReadFile`. ([internal/integration/instructions.go:65-80](../../internal/integration/instructions.go#L65-L80)) The sequential stale-preview and human-edit tests are useful but do not exercise a writer between final read and rename/unlink. ([internal/integration/instructions_test.go:38-69](../../internal/integration/instructions_test.go#L38-L69)) This can lose user data even without a malicious actor.

#### F-09 — Medium: archive, publish, diff-output, and install paths are not uniformly no-follow/atomic

Archive reads perform `Lstat`/`Stat`/open by pathname, and the existing-directory resolver follows a final symlink. ([internal/archive/archive.go:88-140](../../internal/archive/archive.go#L88-L140)) Restore copies into a new destination directly and sanitizes records only after all files are written; an interrupted or failed restore can leave a partially populated destination that is not marked unusable. ([internal/archive/archive.go:258-358](../../internal/archive/archive.go#L258-L358)) `Publish` calls `MkdirAll` before checking only the final component for a symlink, so a symlinked ancestor is not rejected. ([internal/publish/publish.go:17-46](../../internal/publish/publish.go#L17-L46)) `diff --output` opens the requested path without `O_NOFOLLOW` or an atomic staging protocol. ([internal/cli/advanced.go:293-343](../../internal/cli/advanced.go#L293-L343)) The Makefile install target checks nonexistence and then invokes an overwriting `install` command, leaving a check/use race. ([Makefile:57-61](../../Makefile#L57-L61)) These are local operator paths, not remote privilege boundaries, but should use one reviewed output-path policy.

#### F-10 — Medium: the budget ledger is not task admission and has a nil/error panic

The ledger's own documentation says cap zero means no enforcement, and its tests only call the store methods directly. ([internal/store/budget.go:12-23](../../internal/store/budget.go#L12-L23), [internal/store/budget_test.go:9-77](../../internal/store/budget_test.go#L9-L77)) No production task/workflow/service path calls `SetBudgetCap`, `Charge`, or `BudgetReset`; a new task key or a retry/provider/session change can start with fresh accounting. ([internal/tasks/tasks.go:325-455](../../internal/tasks/tasks.go#L325-L455), [internal/workflow/workflow.go:497-519](../../internal/workflow/workflow.go#L497-L519)) The project plan itself acknowledges that the ledger is not bound to task execution. ([docs/PLAN_ALL.md:23-30](../../docs/PLAN_ALL.md#L23-L30))

`BudgetUse` dereferences the returned pointer before checking the error. ([internal/store/budget.go:24-29](../../internal/store/budget.go#L24-L29)) A closed/corrupt store or invalid ledger can therefore panic instead of returning an error. `Total` and per-owner addition also use `int`; although the normal 64-bit limits make overflow costly, the accounting type is not overflow-safe. ([internal/store/budget.go:74-99](../../internal/store/budget.go#L74-L99), [internal/store/budget.go:124-131](../../internal/store/budget.go#L124-L131)) Add closed-store/corrupt-ledger and large-ledger regression tests before treating this as admission control.

#### F-11 — Medium: resource reservations are labels, and admission happens after workspace creation

`Acquire` provides a transactional coordination lock and the source comments correctly say it is not filesystem access control. ([internal/store/resources.go:18-20](../../internal/store/resources.go#L18-L20), [internal/store/resources.go:31-64](../../internal/store/resources.go#L31-L64)) It does not bind a named port/database, provision a service, or isolate a browser profile. Task execution creates the Git worktree and materializes the base before checking capacity/acquiring reservations. ([internal/tasks/tasks.go:277-323](../../internal/tasks/tasks.go#L277-L323)) Many queued tasks can therefore consume disk/worktree resources before admission blocks them; there is no global disk quota or garbage collection. ([docs/ARCHITECTURE.md:63-66](../../docs/ARCHITECTURE.md#L63-L66)) Existing tests prove same-store lease serialization, not OS-level isolation or multi-connection stale-lease recovery. ([internal/store/resources_test.go:9-84](../../internal/store/resources_test.go#L9-L84))

#### F-12 — Medium: workflow recovery can strand live child work and can leave PID-zero workflows stuck

Workflow node tasks are independently detached supervisors. ([internal/workflow/workflow.go:503-519](../../internal/workflow/workflow.go#L503-L519), [internal/tasks/tasks.go:130-193](../../internal/tasks/tasks.go#L130-L193)) If the workflow supervisor dies, `workflow.Reconcile` marks only the workflow `LOST`; it does not cancel, fence, or release all child task IDs. ([internal/workflow/workflow.go:598-627](../../internal/workflow/workflow.go#L598-L627)) A child supervisor can remain alive and complete after the parent is reported lost. The workflow goroutine also discards `tasks.Execute` errors. ([internal/workflow/workflow.go:519-519](../../internal/workflow/workflow.go#L519-L519)) A queued/integrating workflow with `PID == 0` and an old timestamp is never marked gone because `DefinitelyGone(0, ...)` is false on Linux. ([internal/workflow/workflow.go:617-623](../../internal/workflow/workflow.go#L617-L623)) Add fault-injection tests for parent loss, child completion, task error, and missing PID.

#### F-13 — Medium: event history and outcome/review records are not a complete immutable evidence chain

The SQLite events table stores a payload, but the public `Events` method returns only sequence, event kind, reference, and timestamp. ([internal/store/sqlite.go:242-244](../../internal/store/sqlite.go#L242-L244), [internal/store/sqlite.go:453-465](../../internal/store/sqlite.go#L453-L465)) Records can be overwritten by `Put`, with no hash chain or immutable event digest. `Review` binds an investigation/candidate/config digest but does not verify that all referenced snapshots and artifacts still exist before recording approval. ([internal/assurance/verify.go:254-266](../../internal/assurance/verify.go#L254-L266)) The CLI `outcome` command accepts a label for any investigation ID without requiring a finished investigation, valid candidate, or existing artifacts. ([internal/cli/cli.go:739-768](../../internal/cli/cli.go#L739-L768)) This is especially risky because a user-facing outcome artifact can be copied into a later learning dataset, even though outcome labels are explicitly local assertions. ([internal/learning/learning.go:187-218](../../internal/learning/learning.go#L187-L218))

`Sign` verifies referenced config/output/report blobs at signing time and signs the embedded investigation plus an artifact hash list, but the envelope does not include the event history or a complete independent manifest of all snapshot records. ([internal/attestation/sign.go:109-147](../../internal/attestation/sign.go#L109-L147)) Content-addressed IDs provide useful indirect binding, but signature validity is not event retention, independent administration, or correctness.

#### F-14 — Medium: promoted learning order is mutable after promotion

`Promote` checks the proposal and dataset digests at promotion time, but `LoadOrder` later validates only that the stored order is a complete permutation of the current config. It does not recheck equality with the evaluated proposal, evaluation digest, or dataset digest. ([internal/learning/learning.go:354-394](../../internal/learning/learning.go#L354-L394)) A local store mutation can replace a promoted order with another complete permutation and still pass `LoadOrder`. The existing regression mutates the proposal after evaluation, not the promoted strategy record. ([internal/learning/learning_test.go:73-91](../../internal/learning/learning_test.go#L73-L91)) This is not protection from a malicious local administrator, which the model disclaims, but it is a concrete integrity gap in the learning authority contract.

#### F-15 — Medium: redaction is best effort and raw check output can enter repair prompts/provider boundaries

Context search excludes a useful filename list and applies several regexes, but common quoted JSON credentials and other formats are not covered; the code labels the result best effort. ([internal/contextstore/context.go:35-67](../../internal/contextstore/context.go#L35-L67), [internal/contextstore/context.go:79-114](../../internal/contextstore/context.go#L79-L114)) Repair feedback appends raw stdout/stderr content, merely stripping terminal controls, to the next agent prompt. ([internal/tasks/tasks.go:463-484](../../internal/tasks/tasks.go#L463-L484), [internal/execution/process.go:273-285](../../internal/execution/process.go#L273-L285)) A native provider adapter could consequently receive secrets emitted by a check. The security model already says evidence/context may be sensitive, but there is no policy or test that prevents provider transfer. The demo harnesses also pass all non-Git host environment variables into fixture commands. ([scripts/demo.py:32-35](../../scripts/demo.py#L32-L35), [scripts/demo_extended.py:21-24](../../scripts/demo_extended.py#L21-L24))

#### F-16 — Medium: SDK output limits are checked too late or incompletely

The Go SDK accumulates stdout and stderr in unbounded `bytes.Buffer` values and checks `MaxOutput` only after the child exits. ([sdk/go/rover_client.go:80-103](../../sdk/go/rover_client.go#L80-L103)) The Python SDK bounds stdout through a temporary file but allows stderr to grow without a configured limit. ([sdk/python/rover_client.py:35-54](../../sdk/python/rover_client.py#L35-L54)) The TypeScript SDK uses `spawnSync` and `maxBuffer`, so it is better bounded, but all three wrappers kill only the direct client process on timeout and do not establish a client-side process-group cleanup contract. ([sdk/typescript/src/rover_client.ts:51-85](../../sdk/typescript/src/rover_client.ts#L51-L85)) Existing SDK tests cover argv/non-JSON behavior only, not output bombs, timeout descendants, or permission changes. ([sdk/python/test_client.py:7-23](../../sdk/python/test_client.py#L7-L23), [sdk/typescript/test/client.test.ts:8-33](../../sdk/typescript/test/client.test.ts#L8-L33), [sdk/go/rover_client_test.go:10-47](../../sdk/go/rover_client_test.go#L10-L47))

#### F-17 — Medium: release supply-chain controls are weaker than the comments imply

The release workflow grants both `contents: write` and unused `id-token: write`. ([.github/workflows/release.yml:12-15](../../.github/workflows/release.yml#L12-L15)) A dispatched release can therefore expose OIDC capability to arbitrary build/test code even though the comments say no signing credentials are injected. The `version` input is interpolated into `$GITHUB_ENV` and the release tag without format validation. ([.github/workflows/release.yml:32-34](../../.github/workflows/release.yml#L32-L34), [.github/workflows/release.yml:53-58](../../.github/workflows/release.yml#L53-L58)) The checkout pin in release is not the same 40-character SHA as CI: release line 23 contains a 39-character string, while CI line 16 contains a different 40-character SHA. ([.github/workflows/ci.yml:16-19](../../.github/workflows/ci.yml#L16-L19), [.github/workflows/release.yml:23-26](../../.github/workflows/release.yml#L23-L26)) The “SBOM” target is raw `go list -m -json all` plus build info, not a standard SPDX/CycloneDX document, and the scanner is `@latest`. ([Makefile:45-55](../../Makefile#L45-L55)) The release job also does not run demos, schema checks, or `doctor --verify` before attaching artifacts. ([.github/workflows/release.yml:35-52](../../.github/workflows/release.yml#L35-L52))

#### F-18 — Low/Medium: protocol and platform documentation overstates negotiation/option behavior

MCP initialization accepts any nonempty requested protocol version and returns Rover's fixed version; it does not reject an unknown requested version despite the CLI reference saying unknown versions are not claimed. ([internal/mcp/protocol.go:88-107](../../internal/mcp/protocol.go#L88-L107), [docs/CLI.md:141-149](../../docs/CLI.md#L141-L149)) `RunHTTP` has an `allowPlaintextLoopback` parameter, but the earlier non-loopback check rejects missing TLS unconditionally; the CLI flag description says it can allow plaintext non-loopback. ([internal/mcp/http.go:143-169](../../internal/mcp/http.go#L143-L169), [internal/cli/server.go:30-34](../../internal/cli/server.go#L30-L34)) The production server calls `HTTP(s)` without an allowed-host list, and the TLS tests exercise an `httptest` TLS client/server helper rather than `RunHTTP` with a real certificate/key. ([internal/cli/server.go:55-75](../../internal/cli/server.go#L55-L75), [internal/mcp/client_test.go:35-74](../../internal/mcp/client_test.go#L35-L74))

Generic agent argv substitution replaces every exact `{{objective}}` occurrence, while the configuration guide says it is one standalone substituted argument. ([internal/agents/agents.go:71-87](../../internal/agents/agents.go#L71-L87), [docs/CONFIGURATION.md:51-57](../../docs/CONFIGURATION.md#L51-L57)) This is not implicit shell injection because argv remains explicit, but it is a contract mismatch that can change command semantics.

#### F-19 — Medium: SQLite state admission and migration coverage are too narrow

`Open` treats any existing regular file named `rover.db` as a candidate Rover store and then attempts to open/mutate it; it does not validate a store marker or required schema shape before initialization. ([internal/store/sqlite.go:174-207](../../internal/store/sqlite.go#L174-L207)) The only schema evolution is creation at version 0 and rejection of versions greater than 1; there is no migration ladder, interrupted-migration state, or compatibility test. ([internal/store/sqlite.go:225-258](../../internal/store/sqlite.go#L225-L258)) Restore checks SQLite `quick_check` but does not independently validate that every expected table/record is present. ([internal/archive/archive.go:307-313](../../internal/archive/archive.go#L307-L313)) The roadmap correctly leaves upgrade recovery and complete retention for later, but the status language should not imply a tested upgrade path. ([ROADMAP.md:13-24](../../ROADMAP.md#L13-L24))

### Inferences

- The strongest security property is fail-closed interpretation of incomplete observations, not isolation: timeout, truncation, malformed report, wrong candidate, missing required check, and future schema are generally refused rather than converted to PASS. ([internal/assurance/parse.go:22-52](../../internal/assurance/parse.go#L22-L52), [internal/assurance/verify.go:51-107](../../internal/assurance/verify.go#L51-L107), [internal/store/sqlite.go:225-238](../../internal/store/sqlite.go#L225-L238))
- The main architectural risk is authority ambiguity. A same-user process can read host resources by design, but it can also race state paths or mutate a controller record; therefore “frozen,” “retained,” “verified,” and “reviewed” should be described as integrity hygiene under a trusted controller, not as tamper-resistant evidence against the worker.
- The current evidence is strongest for deterministic fixture behavior and weakest for adversarial worker behavior, release provenance, resource exhaustion, and recovery after partial supervisor failure.
- The documented local threat model is generally honest. The problem is not that Rover hides the lack of a sandbox; it is that aggregate status and validation language can make adjacent proxies appear to satisfy broader original acceptance conditions.

### Gaps

- No hostile repository/worker was run. No exploit was attempted against path races, SQLite tampering, XML nesting, Docker, PTY sockets, or provider credentials.
- No independent host, organization identity, protected CI publisher, remote worker fencing, credential broker, SSO/OAuth, hostile-code isolation, or live Codex/Claude account was available or tested.
- The review did not run a schema validator because `jsonschema` is not installed in the current Python environment; the committed schemas were read and runtime examples were covered only by existing tests.
- The current audit did not run a real TLS `RunHTTP` server, Docker daemon, Windows build, macOS unit-specific PTY test, or full five-target fuzz aggregate. These are evidence gaps, not inferred passes.
- TOCTOU findings are code-review findings. They require a controlled concurrent writer to turn into a demonstrated race and should not be reported as observed exploits without such a test.
