# Rover Rust Port and Feature Parity Plan

Status: implementation in progress. Initial plan date: 2026-09-24; source pins updated 2026-09-25.

## User-approved direction

- Rebuild Rover in Rust and keep product interfaces to CLI and TUI.
- Remove the Python, TypeScript, and Go SDKs.
- Bring the published feature sets of Herdr, Luvus, and Orca ADE into Rover.
- Preserve existing Rover behavior unless a specific removal is recorded.
- User clarified: port all behavior into Rust CLI/TUI; reuse upstream source only when an exact-path audit permits it.

## Scope and conflicts to resolve

Target capability parity through CLI/TUI, not pixel-for-pixel reproduction of desktop interaction. Drag/drop maps to a path picker or explicit file command; browser design selection maps to DOM inspection, selector targeting, and retained evidence; mobile companion semantics map to remote CLI/TUI access. These equivalents count only after acceptance tests pass. No separate desktop, web, or mobile UI is included under the chosen product surfaces.

Orca ADE contains substantial Electron/React/TypeScript, mobile, and cloud code. These are behavior references to port into Rust CLI/TUI, not additional Rover applications. No upstream source is copied before path-level license and attribution audit.

At the pinned revisions in `UPSTREAM_SOURCE_AUDIT.md`, Herdr is Apache-2.0, Luvus README and root LICENSE both state Apache-2.0, and Orca ADE root LICENSE is MIT. Rover is currently MIT. Luvus's earlier indexed README/metadata conflict is resolved for that exact pinned commit only. Each nested license, notice, asset and dependency still requires an import-specific audit. This is an engineering plan, not legal advice.

## Capability inventory

Herdr: persistent server/client and named sessions; workspaces, tabs, split/zoom/popup panes; keyboard/mouse controls; detach/reattach, restore, scrollback/history replay, supported native-agent resume and experimental live handoff; agent detection/state/integrations/direct attach/agent control; worktree provenance; notifications; CLI/socket API; plugins/event hooks; themes/keybindings/sidebar configuration; SSH attach, saved machines, multi-machine visibility/reconnect; platform-specific behavior.

Luvus: persistent terminal sessions and status sidebar; task board, drafts, dependencies, retries and history; worktree or shared-workspace workers; path leases; quality/merge gates; scheduled/one-shot automations and misfire recovery; reviewed unattended profiles and explicit access modes; Git/PR/issue workflows; file browser/viewer/editor/diff; remote SSH; notifications; themes/keybindings/localization; CLI/socket/UHP; language-neutral modules with preview, ref pinning, event hooks and module-owned config/state.

Orca ADE: parallel worktrees/fan-out comparison; terminal splits and persistent scrollback; agent profiles/account/usage visibility; editor/file browser/file/image handoff/diff comments; GitHub/Linear tasks, PRs, issues, boards, CI/conflicts/review; Markdown/image/PDF previews; embedded browser, DOM/design inspection and computer-use controls; local/SSH/self-hosted/ephemeral remote modes, reconnect/port forwarding; notification inbox/unread state; CLI automation for worktrees/terminals/browser/UI; schedules/artifacts/skills; mobile companion semantics mapped to CLI/TUI.

Existing Rover behavior to retain: source capture/diff/composition, tasks/process supervision/PTy, DAG workflows, strict config/scoped grants, structured Go/JUnit/SARIF/check interpretation, replay/counterfactual/mutation checks, evidence/review, MCP/remote CLI, context/memory, backup/restore, Ed25519 attestation, learning/evaluation. Each behavior must have a Rust acceptance mapping before Go removal.

## Rust architecture decisions required

Use a Rust workspace and stable serialized contracts. Candidate crates: model, store, source, execution, terminal, agents, assurance, workflow, remote, plugins, tui, cli. Finalize boundaries in ADRs. Select TUI, PTY, SQLite, async, SSH, browser, notification, and test dependencies only after an ADR records alternatives, license, supported platforms, maintenance, security assumptions, and acceptance evidence. Use SQLite migrations and an explicit Go-to-Rust state importer; never reinterpret old state silently.
