# Configuration and command contracts

The alpha accepts **JSON only** (`rover/v1alpha1`). Unknown fields, duplicate keys,
noncanonical field capitalization, omitted required safety fields, and null required
fields are errors. The compiled semantic validators remain authoritative; JSON Schema
files assist editors and do not replace runtime checks.

## Verification

```json
{
  "schema": "rover/v1alpha1",
  "checks": [
    {
      "id": "unit", "argv": ["go", "test", "-json", "-count=1", "./..."],
      "timeout": "5m", "required": true,
      "parser": "go-test-json", "min_tests": 1
    },
    {
      "id": "vet", "argv": ["go", "vet", "./..."],
      "timeout": "5m", "required": true, "parser": "exit-code"
    }
  ],
  "policy": {"require_review": true, "review_paths": ["internal/auth/**"]}
}
```

Approved defaults come from `.rover/config.json` inside the selected base snapshot.
`--config /path/file.json` is an explicit, recorded same-user override, not a protected
organization-policy feature. Worktree changes to the default config produce a finding.

Each check runs in a **new copy of the candidate**, so files generated by one check
are not silently prerequisites of another. No Git metadata is materialized for checks.
Commands relying on `.git`, a shared build directory, or external state need a reviewed
alternative; this alpha has no service provisioning or dependency graph.

## Parsers

- `exit-code`: successful exit only; `min_tests` and `report_path` are not allowed.
- `go-test-json`: parse stdout test events; requires `min_tests >= 1`, actual non-skipped
  test execution, package/test terminal events, no failures, complete parse, and exit zero.
- `junit`: requires a safe relative `report_path` and `min_tests >= 1`. Reports must be
  newly generated in this check (not present in the source snapshot). Counts actual
  testcases, not a fabricated root `tests` attribute. Failures/errors/only skipped cases
  cannot satisfy an expected passing test requirement.

A candidate-controlled test runner can still produce dishonest output. Parsing validates
the output contract, not the truth of arbitrary code or requirements. Formal, security,
and compatibility interpretations are not implemented.

## Task fields

`schema`, `objective`, `repository`, `base`, `argv`, `timeout`, and `auto_verify` are
explicit. Optional: `pass_env`, `config_path`, and `depends_on`. Nonempty `depends_on`
is rejected because DAG scheduling is not implemented. Repositories/config paths
resolve relative to the task file. Standalone `{{objective}}` is one substituted argv
argument. There is no implicit shell expansion.

Timeouts: 1 ms through 24 hours. At most 128 checks / 128 argv elements. Check IDs use
ASCII letters/digits and `_.-`, beginning with a letter/digit, at most 128 characters.
Review globs support `*`, `**`, `?`; unsupported syntax is rejected.

## Environment and authentication

The local worker inherits PATH and uses isolated HOME/TMPDIR/GOCACHE/GOPATH. Default
GOPROXY=off and GOTOOLCHAIN=local prevent surprise Go downloads, but they do not block
network access by arbitrary local programs. `pass_env` explicitly names variables to
inherit. Inherited values are not put in metadata, but the command can print them.
Do not assume redaction. Passing HOME or credentials widens exposure substantially.

Dependencies must be made available through your reviewed environment. Projects with
uncached Go dependencies will fail until you explicitly configure the environment;
Rover does not automatically install or upload anything.

## Results

Execution exit, interpreted check result, policy decision, and review are separate.
Required failure => BLOCKED. Missing/error/truncated/wrong-subject evidence => INCONCLUSIVE.
Zero required checks => INCONCLUSIVE. Required checks pass plus configured review or
change findings => REVIEW_REQUIRED. Otherwise ACCEPTED under the supplied policy.
A local review adds a separate record without changing that decision.

Global `--state` must precede the subcommand. For read `report`/`status`, process exit
zero means the read succeeded, not that the referenced change was accepted. Verify
uses 0/1/2/3 for accepted/blocked/inconclusive-or-error/review-required.
